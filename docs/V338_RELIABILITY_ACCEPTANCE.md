# 3.3.8 桌面可靠性验收

## 交付边界

代码基线：3.3.7 / 3789e03。此修复候选不扩展 Windows v3.3 冻结范围，不改 AGC 持久发布身份，不从修复分支签发用户包。

本轮执行了 `.github/scripts/test-capsule-runtime.cjs`：28 项 Node 断言通过。它直接转译生产逻辑，窗口 / 存储 / Ability 为显式模拟对象，可验证控制流和故障回退，不能验证真实系统合成、绘制、焦点或跨应用层级。现有 Hypium 套件新增 5 项就绪与分页测试，由正常 HarmonyOS Build 执行编译 / Local Test 门禁；Linux 超时回退不能记为 Hypium 断言执行通过。远端 CI 的实际结果以相应 PR 检查为准。

## 必须保持的不变量

- pending collapse 不写入持久数据，不提前把原纸片变成小胶囊或关闭。
- startAbility 成功仅代表请求已接受。必须等待当前 owner token 与 request revision 的就绪确认。
- 初始顺序：父宿主配置完成 → 创建子窗口 → 几何 → 内容 → 原生 mask → show → 交互 → ready。
- 原生掩码失败、父宿主锚点被系统调整、显示失败或 6 秒就绪超时，不允许用矩形透明窗口冒充正常胶囊。
- 失败锁存到本次进程，显式“重试侧边胶囊”解除；所有已折叠可见纸片回退为展开纸片，不反复创建 / 关闭窗口。
- 用户在交接中隐藏 / 删除纸片或关闭侧边模式，迟到的成功回调不能重新折叠或复活纸片。
- 分页保持所有成员可达，最大原生高度限制在可用工作区，翻页条也纳入掩码。
- 退出前第一次 / 第二次 flush 任一失败都不执行 killAllProcesses。

## 仍需关注

父宿主右下角一像素锚点继续是兼容方案。本轮增加了位置读回、严格校验与失败回退，但没有真机证据证明它在所有 2in1 系统构建都可用。若设备不允许该锚点，应保留展开纸片和诊断，不恢复不受控的主窗口透明回退，也不声称胶囊已修复。测试期间不记录笔记内容、文件授权 URI 或签名密钥。
